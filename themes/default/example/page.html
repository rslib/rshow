How rshow serves a version

A published folder is stored once, named by the hash of its files, and served under a slug that never changes.

What a publish does

Publishing walks the folder and hashes every file. The host answers with the hashes it already holds, so the client uploads only the files that are missing. The version record is the manifest: a list of path, hash, size and media type. Nothing is rebuilt and nothing is copied, because a version is a set of names for files that are already on disk.

Two consequences follow. A republish of a mostly unchanged folder is cheap, and an old version keeps serving after a new one is published. The link at art.example.com/<slug>/ points at the newest version unless the artifact is pinned, in which case it points at the pinned one.

A token override

A page that needs one colour of its own sets it after the theme links, in a single :root block. The rest of the palette keeps its roles.

<style>
:root { --accent: #0f62fe; }
@media (prefers-color-scheme: dark) {
  :root:not([data-mode="light"]) { --accent: #78a9ff; }
}
:root[data-mode="dark"] { --accent: #78a9ff; }
</style>

A token that carries text has to be set for both modes, because a colour that reads on white is not a colour that reads on g100. A token that only fills a shape can be set once.

What the reader sees

Body text sits at 18px on a 1.6 line and stops at about 72 characters. A heading above a paragraph is a weight change, not a colour change, and there is no label above a heading. Tables rule their rows in the lightest line in the palette and give numbers a tabular figure, so columns line up.

  • A row rule is information: it separates one record from the next.
  • An axis line is information: it marks zero on a chart.
  • Anything else would be decoration, so the theme ships none.

The report layout in report.css and report.js numbers the sections, figures and tables, resolves cross-references and puts footnotes in the margin.
