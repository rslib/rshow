Two kinds of terminal

A capture is a screen: it keeps the escape sequences of a full screen program and loses the timing. A recording is a stream: it keeps the timing and replays it. Both sit in the same window frame here, and both read on a light and a dark ground.

How to take them

Both fit in a repository next to the page that shows them, and both are text, so a version diff is a readable diff.

tmux capture-pane -pet <target> > capture.ans
asciinema rec demo.cast

capture-pane -e keeps the escape sequences and -p prints instead of pasting, so the result is the screen as it looks, ready to be committed. -t names the pane or window to copy. For the recording, asciinema rec writes an asciicast v2 file; ctrl-d ends it. Keep the capture to the grid it was taken on and say so in data-cols and data-rows, or the frame will be the wrong shape.

A palette per figure

Neither viewer carries colours of its own: the sixteen ANSI colours live in terminal.css and the viewer reads them back. data-palette picks the set.

  • default: the page ground, light or dark, with a neutral sixteen that holds on either, so nothing has to be recorded twice.
  • dark and light: a fixed ground, for a capture that is about being dark.
  • high-contrast: black on white in a light page, white on black in a dark one.

When a library does not arrive

A missing CDN costs colour, not content: the capture falls back to plain text with the escapes stripped. A recording needs its player, so it says so and links to the file.
