rshow theme default

IBM Carbon v11 in two modes: white (light) and g100 (dark), system by default. Plex Sans for text, Plex Mono for code and data, square corners, one blue for anything interactive and Carbon's eight colour data palette. A 1280x720 deck canvas with twelve layouts, a prose page, and a report layout with contents and side notes, then the rest of the set: a project page, a poster, a dashboard, mockups in platform skins, sketches, terminal captures and TUIs.

Modes

One theme, two modes. The light values sit on :root in tokens.css, the dark values appear under prefers-color-scheme: dark and again under :root[data-mode="dark"]. The attribute wins, so a reader can go against the system. mode.js reads the storage key rshow-mode (values light, dark, system) in the head, before the body paints, and the button in the corner cycles the three. A deck does the same thing on the key t. Print is always light.

The chips below follow the mode this page is in. Press the button in the corner, or set your system to dark, and they change.

Colour roles

Each colour has one job and only that job. The chips follow tokens.css and the ground page.css picks for your system appearance, and each value under a chip is read from this page at load with getComputedStyle(document.documentElement).getPropertyValue.

Contrast on the ground: text 18.1:1, secondary text 7.8:1, accent 5.0:1 in light, and text 16.5:1, secondary 10.6:1, accent 7.7:1 in dark: all above the 4.5:1 floor. The support colours are data marks and never text, because green on white is 3.4:1.

Layouts

Every layout the theme ships, one frame each. A frame is lazy loaded, so the page stays light on a phone, and the link under it opens the same example full size. The deck, the page, the report, the project page, the poster and the dashboard are documented templates: the markup is the starting point, and a page may add its own layouts and classes on top, with colours from the tokens. The mockups, the sketches, the terminals and the tuis are guided kits: they give an agent a frame, a floor and a set of rules, and the drawing is the work.

Usage

A published deck links the theme files at one pinned version, one link per file, then overrides a token in its own later style block:

<link rel="stylesheet"
  href="/_themes/default@<n>/fonts.css">
<link rel="stylesheet"
  href="/_themes/default@<n>/tokens.css">
<link rel="stylesheet"
  href="/_themes/default@<n>/deck.css">
<script src="/_themes/default@<n>/deck.js"></script>
<style>:root{--accent: #0f62fe;}</style>

A page uses the same paths with page.css in place of deck.css, adds mode.js in the head and links no other script. A report swaps page.css for report.css and adds report.js with defer. The value in the override above is this theme's accent, so it changes nothing until you give it a colour of your own. Replace @<n> with the version rshow theme list prints.
